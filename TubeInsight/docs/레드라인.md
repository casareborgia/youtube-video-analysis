  
■ 핵심 결론 다섯 줄

1\. 모델이 절반이다. 초기 나노바나나(Gemini 2.5 Flash Image)는 한글이  
   구조적으로 깨진다. 최종본은 나노바나나 프로, 시안은 나노바나나2로.  
2\. 텍스트는 전부 따옴표로 직접 지정한다. 문구당 2\~5단어(10자 내외),  
   한 장에 3\~5개 이하, 폰트·색·위치까지 서술한다.  
3\. 숫자·치수는 AI가 지어내지 않는다. "수심 55m", "1994" 같은 값은  
   반드시 프롬프트에 그대로 써 준다.  
4\. 프롬프트는 \[장면\] → \[주석 레이어\] → \[텍스트\] → \[제약\] 4블록으로 쌓고,  
   항상 "지정한 텍스트 외 글자 금지"로 닫는다.  
5\. 80% 맞으면 리롤하지 말고 편집한다. 완벽해야 하는 제목은 빈 패널로  
   뽑고 후보정(미리캔버스/Canva/포토샵)으로 얹는다.

■ 1\. 모델 선택 — 한글이 갈린다

· 나노바나나 (Gemini 2.5 Flash Image, 2025.8)  
  한글 사실상 불가(자모 분리·뭉개짐). 사용하지 않음.  
· 나노바나나 프로 (Gemini 3 Pro Image, 2025.11) ← 최종본용  
  한글 오류율 약 7%, 짧은 문구는 체감 90% 이상. 손글씨체 한글도 가능.  
  인포그래픽·주석·다국어 텍스트 최강. 2K/4K, 레퍼런스 이미지 최대 14장.  
· 나노바나나2 (Gemini 3.1 Flash Image, 2026.2) ← 시안용  
  빠르고 저렴, 한글 배너 무보정 수준. 구도 탐색용 시안 3\~5장에 사용.

팁: 제미나이 앱에서는 '사고하기(Thinking)' 모델 \+ 이미지 생성 도구를  
선택해야 프로가 잡힌다. API에서는 종횡비를 프롬프트가 아닌 설정값으로:  
aspect\_ratio: "16:9", image\_size: "2K" (대문자 K).

■ 2\. 이 스타일의 해부 — 3개 레이어

L1 장면: 미니어처 디오라마 3D 렌더  
  사실적 3D 렌더링 \+ 미니어처 디오라마 톤, 무광(matte) 재질,  
  소프트 스튜디오 조명, 부드러운 앰비언트 오클루전.  
  시점은 아이소메트릭 부감 / 항공뷰 / 단면 컷어웨이.  
  사람은 "얼굴 없는 흰색 마네킹 피규어(흰 방호복)"로.

L2 주석: 빨간 공학 주석 오버레이  
  점선 리더선 \+ 끝점 동그라미, 화살표, 양끝 화살표 치수선,  
  각도 원호, 대괄호, 루트 트레이스, 큰 물음표.  
  색은 빨간색 하나로 통일. "기술 도면·정비 매뉴얼 스타일" 명시.

L3 텍스트: 한글 라벨 \+ 숫자  
  굵은 고딕체 흰색 \+ 검은 반투명 띠, 빨간 박스 배경 헤더 라벨,  
  초대형 빨간 숫자, 짙은 남색 정보 패널.

참고: 예시 썸네일 속 "TIK" 같은 표기는 AI가 지어낸 무의미 텍스트.  
"지정한 텍스트 외 글자 금지" 제약이 이걸 막는 장치다.

■ 3\. 마스터 템플릿 (기본형 — { } 슬롯만 바꿔 사용)

──────────────────────────────────────  
16:9 유튜브 썸네일 이미지를 2K 해상도로 생성해줘.

\[장면\]  
{피사체와 상황}을 보여주는 사실적인 3D 렌더링.  
시점은 {aerial view / isometric 45° / cutaway cross-section}.  
미니어처 디오라마 느낌, matte materials, soft studio lighting,  
soft ambient occlusion. 사람은 얼굴 없는 흰색 마네킹 피규어  
(흰색 방호복)로 표현.

\[주석 레이어\]  
이미지 위에 기술 도면 스타일의 빨간색 주석 오버레이를 얹어줘.  
주석 색은 빨간색 하나로 통일하고, 선은 얇게:  
\- {대상 A}를 가리키는 빨간 점선 리더선 \+ 끝점 동그라미, "{라벨 A}" 라벨  
\- {위치}에 양끝 화살표 치수선과 "{55m}" 치수 표기  
\- {그 외: 각도 원호 "90°" / 루트 점선 / 큰 물음표 등}

\[텍스트\]  
\- {좌상단}에 빨간 사각 박스 \+ 굵은 고딕체 흰색으로 "{헤더 라벨}"  
\- {하단 중앙} 검은 반투명 띠 위에 흰색 고딕체로 "{자막 문구}"  
\- 모든 텍스트는 정확한 철자로, 크고 선명하게

\[제약\]  
위에 지정한 텍스트 외에는 어떤 글자·숫자도 넣지 마.  
모든 주석선과 화살표는 반드시 실제 대상을 정확히 가리켜야 해.  
──────────────────────────────────────

슬롯을 채울 때:  
\- 문구는 짧게: 라벨 2\~5단어, 10자 내외. 텍스트 요소 3\~5개가 안전선.  
\- 숫자는 전부 명시: 치수선은 그려 주지만 값은 지어내지 않는다.  
\- 여백이 필요하면 수치로: "우측 1/3은 텍스트용 빈 공간(최소 20%)".  
\- 스타일·카메라 용어는 영어가 더 잘 듣는다.

■ 4\. JSON 템플릿 (시리즈 일관성·자동화용)

스타일 블록은 고정하고 scene / annotation\_layer / text\_layer만 교체.  
탐색 단계는 자연어가 낫고, JSON은 재현성이 필요할 때 쓴다.

■ 6\. 한글·숫자 렌더링 10계명

01 프로 또는 나노바나나2로 생성한다. 구형 Flash의 한글 깨짐은  
   프롬프트로 못 고친다.  
02 2K 이상으로 뽑는다. 1K에서는 작은 글씨가 뭉개진다.  
03 모든 문구를 따옴표로 지정한다. 문구 \+ 폰트 느낌(굵은 고딕체) \+  
   색 \+ 위치 \+ 크기를 한 세트로.  
04 짧게 쓴다. 문구당 2\~5단어(10자 내외), 한 장에 3\~5개까지.  
   온-이미지 텍스트 총량이 많아질수록 전체가 불안정해진다.  
05 숫자·치수·연도는 전부 직접 명시한다. 치수 "선"은 그려 주지만  
   "값"은 프롬프트에 준 것만 신뢰할 수 있다.  
06 "지정한 텍스트 외 글자 금지" 제약을 항상 넣는다.  
   유령 라벨(TIK 등)을 막는 유일한 방법.  
07 텍스트를 먼저 확정한다(text-first). 문구를 대화로 먼저 확정한 뒤  
   "이 텍스트로 이미지를 만들어줘" 순서가 정확도를 높인다. (구글 공식 팁)  
08 80% 맞으면 편집으로 마무리한다. "다른 요소는 그대로 두고 텍스트만  
   'OO'로 정확하게 고쳐줘". 레이아웃이 흔들리면 "레이아웃과 이미지는  
   그대로, 텍스트만 제자리에서". 5\~7턴 넘으면 새 대화로.  
09 스타일 키워드는 영어를 섞는다. 내용은 한국어, matte materials /  
   soft studio lighting / cutaway 같은 스타일·카메라 용어는 영어로.  
10 픽셀 퍼펙트가 필요하면 후보정한다. 핵심 카피는 검은 띠·빈 패널만  
   생성하고 미리캔버스·Canva·포토샵에서 실제 폰트로 얹는다.

■ 7\. 실패 모드 → 처방

· 한글 오타·깨진 글자  
  → 프로 \+ 2K \+ 문구 단축. 편집 턴으로 "철자를 정확히 'OO'로 고쳐줘".  
· 치수 숫자가 없거나 임의 값  
  → 모든 수치를 따옴표로 명시. 도면 수준 정확성은 숫자만 후보정.  
· 화살표가 엉뚱한 곳을 가리킴  
  → 콜아웃 수 축소, 대상을 구체적으로 서술, 2패스(장면 먼저 → 주석  
    편집). 안 되면 초안에 손으로 표시해 레퍼런스로 재업로드.  
· 지정 안 한 유령 텍스트 등장  
  → "지정한 텍스트 외 어떤 글자도 넣지 마" 제약 필수.  
· 16:9가 안 지켜짐  
  → API는 aspect\_ratio 설정으로. 편집 때는 입력 이미지 비율을  
    상속하므로 "입력 비율을 바꾸지 마" 명시.  
· 여백 없이 꽉 채움  
  → "우측 1/3은 빈 공간, 최소 20%"처럼 수치로 요구. 또는 텍스트 존을  
    비워 생성 후 후보정.  
· 시리즈 스타일이 조금씩 달라짐  
  → 매 생성마다 같은 스타일 블록 \+ 잘 나온 1\~3장을 스타일 레퍼런스로  
    첨부. "첨부한 썸네일의 스타일과 주석 문법을 그대로 적용해".
